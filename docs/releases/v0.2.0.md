# pManager v0.2.0

Adds the commands an IDE plugin needs to show and undo what pManager did to a
project, plus a stable JSON contract for scripting.

## New commands

### `pman project status <PATH>`

Shows one project's name, state, last change, idle days, git dirtiness and the
next action pManager will take, with its date.

- Measured live, with the same logic as `pman run`, so the result is current
  even between runs.
- `next_action` is `strip`, `archive`, `strip+archive` or `none`.
  `next_action_at` is a local date. It is today when the action is already due,
  and `null` when there is none.
- When nothing is due, `reason` says why (`already archived`, `missing`, ...).
- `dirty` is `null` when the folder is not on disk.

### `pman project restore <PATH>`

Unpacks an archived project back to its original path.

- The archive is unpacked into `<PATH>.part`, its entry count is checked
  against the `.pproject`, and only then is it moved into place.
- The ledger row becomes `registered` and `last_change_at` is set to now.
  The `.pproject` is deleted last. If only that delete fails, the restore
  still succeeds (exit `0`, JSON on stdout) and a warning on stderr names
  the archive to delete by hand.
- Unpacked files get the current time, not their packed timestamps, so the
  next `pman run` does not archive the project again straight away.
- Refuses, and changes nothing, when the project is not archived, when its
  archive is missing, or when `<PATH>` already exists.

## Scripting contract

- `-o json` output of `list`, `project status` and `project restore` is
  described in `docs/schemas/*.schema.json`. `status` and `restore` print an
  array with exactly one object.
- Data goes to stdout, logs and errors go to stderr.
- Exit codes: `0` success, `1` error, `2` invalid arguments, `3` the path is not
  registered.

## Changes

- `status`, `restore` and `remove` find a project by its original path even
  after the folder is gone. The path can use `/` or a different spelling of
  its parent folder, such as Windows 8.3 short names or another letter case.
- `pman project remove` on an unregistered path now exits with `3` instead
  of `1`.

## Known limitations

- An interrupted restore leaves `<PATH>.part` behind. Delete it by hand before
  retrying; restore says so when it finds one.
- Restored files lose their original modification times.

## Notes

The database lives at `pmanager/pmanager.db` in the user data directory
(`%APPDATA%` on Windows). Only `strip/` is looked up next to the executable.
